## 費用を抑える設定

サーバーの `.env.local` に設定し、変更後にサーバーを再起動します。未指定時は `true` です。

```dotenv
ELSEWHERE_SAVE_COSTS=true
```

| 処理 | `true`：節約 | `false`：広く比較 |
| --- | --- | --- |
| 写真の新しい候補を Maps で探索 | 省略 | 実行 |
| Cloud Vision の補助ラベル | 省略 | 使用 |
| 登録済みの写真の視点 | 地点あたり1枚 | 地点あたり最大3枚 |
| Gemini による写真の見比べ | 最大6候補、3件ずつ | 最大18候補、6件ずつ |
| 未準備の候補写真の取得・埋め込み | 最大250地点 | 最大1,500地点 |
| 地形の追加の衛星探索 | 省略し、登録地形で比較 | 指定範囲内で標本を探索 |
| Gemini の出力トークン上限 | 8,192 | 12,000 |

どちらも有料 API を使います。節約モードは無料モードや金額の上限保証ではありません。写真の不一致の除外、出典確認、ユーザーの条件は両方のモードで維持します。公開写真の再利用キャッシュを使い、アップロード写真・埋め込み・景観説明は永続キャッシュに保存しません。

## 人口・水質・治安に関する条件

「人口・水質・治安の参考条件」を開くと、以下を個別に選べます。

| 条件 | 判定 | 元データ |
| --- | --- | --- |
| 国の人口密度 | 100人/km²未満、または500人/km²以上 | World Bank `EN.POP.DNST` |
| 国の良好な水域の割合 | 80%以上 | UNEP / World Bank `EN.H2O.BDYS.ZS` |
| 国の殺人発生率 | 人口10万人あたり3件未満 | UNODC / World Bank `VC.IHR.PSRC.P5` |

しきい値は検索条件であり、公式の「安全」「清潔」の認定ではありません。2020〜2024年の各国・各系列の最新公表値を使い、結果ごとに年、単位、国単位という範囲、出典を表示します。人口密度216か国、水質123か国、殺人発生率136か国の観測値を取得しました。年は系列・国によって異なります。

水質の値は、基準を満たす河川・湖沼・地下水域の割合です。特定の川や海岸の水質、水の透明度、遊泳可否は分かりません。殺人発生率には紛争・盗難・災害などの旅行リスクを含みません。人口密度も、訪問地点の現在の混雑ではありません。

不明な値の候補は、確認できた候補の後に表示します。不明な候補を除外する選択肢もあります。確認できた値が条件を満たさない候補は、両方の設定で除外します。この不明値の選択は新しい3条件に適用し、既存の気候区分・観光客数は従来どおり欠損を採用しません。条件はブラウザーと共有 URL に残します。

```bash
npm run data:factors
```

`data/place-factors.json` は上記の公式 API から作ります。ネットワークがプロキシを必要とする環境では、対応する Node.js の `--use-env-proxy` を指定してスクリプトを実行してください。

## 候補と複数写真の準備

カタログは612地点です。地理情報の候補と、画像の被写体・利用条件を確認した地点は別に数えます。現時点では111地点・112枚の写真を準備しています。鴨川では2枚の独立した Commons 写真を照合・埋め込みし、複数視点の準備処理を実 API で確認しました。500地点すべての写真の確認が完了したという意味ではありません。

```bash
npm run data:discover -- --target=600
npm run data:photos -- --limit=60
npm run catalog:index
# 写真の追加検証と埋め込みも行う場合。Google API を呼び出します。
npm run catalog:index -- --refresh --limit=10
```

Wikidata の座標・国・区分・画像ファイル名・出典から地理候補を追加します。写真の被写体・所在地・ライセンスが未確認の候補には、表示用・比較用の写真を勝手に設定しません。Commons が HTTP 429 を返す場合は、回避せず処理を止め、時間を空けて再開します。`data:photos` の `--limit` は未登録の候補の先頭から数えるため、確認に失敗した候補も毎回含みます。

検索時は `.cache/photo-index-v1.json` を一括で読み、用意した写真から順位を付けます。複数写真がある場合は、最も近い2枚のスコアを平均し、1枚の偶然の構図だけが過大な根拠になるのを抑えます。同じ SHA-1 の写真や比較元と同じ写真は重複して数えません。出典・ライセンス・モデル・プロジェクト・768次元・解析した画像のハッシュを保持します。索引は7日で期限切れになり、未準備の写真を比較する処理へ戻ります。少数地点だけ更新した場合も他の索引を維持します。

BigQuery の地点取得は5,000件までで、応答が複数ページに分かれても取りこぼさないようにしています。この規模ではローカルの正確なコサイン比較を使用し、近似ベクトル索引はまだ作っていません。

## 順位と根拠

上位の写真が不適切だった場合は、設定した確認件数の範囲で次の候補も調べます。写真の確認に失敗した結果は、確認できた結果と区別し、確認できた候補を先にします。明確に弱い景観の一致は除外します。

Maps を使う過ごし方の特徴は、根拠不足を `null` として受け取り、不明という情報を保持します。値の0と不明を同じ意味で比較しません。既存の紹介用特徴は残します。

地形では、平均衛星特徴に加え、3×3の配置を回転・反転も考慮して比較し、標高・傾斜・起伏・水域の観測値を補助に使います。比較元と候補の範囲を同じ物理的な広さにします。対応する範囲のデータを取得できなかった候補を、広さが違う古い値で代用しません。輪郭・島の個数・地形の分類を確定する機能ではありません。

## 評価とフィードバック

詳細画面の「似ている」「あまり似ていない」「地形・風景が違う」は、このブラウザーだけに最大300件を保存します。同じ比較元と選んだ特徴の組み合わせに対して並び順を調整し、地形が違うと評価された候補は除外します。条件の確認済み・不明の優先順は維持します。画像は評価データに含めません。JSON の書き出しができます。

評価は既定では送信しません。詳細画面で「評価を匿名で送って、検索の改善に使う」を選ぶと、場所の ID、選んだ特徴、評価、検索方法、送信日時を Firestore の `feedback` に保存します。アカウントの ID は含めず、文書の ID はブラウザーごとのランダムな値から作ります。住所を出発点にした評価と、撮影場所が不明な写真からの評価は送りません。選択を外すと、このブラウザーに記録が残っている評価を削除します。集計は `npm run eval:feedback` で `.cache/evaluations/feedback.json` に出力します。公開環境で使うには、`npm run google:rules` で Firestore のルールを反映する必要があります。

```bash
npm run eval:discovery
# 仮のラベルを含む動作確認。品質の実測値として扱いません。
npm run eval:discovery -- --include-provisional
# 実際の検索の記録を採点する場合
npm run eval:discovery -- --results=/absolute/path/results.json
```

`data/discovery-benchmark.json` に50件の初期ケースがあります。現在はすべて人による確認待ちです。`npm run eval:review` で確認用の画面（http://127.0.0.1:5199）を開き、候補を採点して確認済みにします。画面には、仮の評価が付いた候補と、現在の順位の上位で未評価の候補を表示します。通常の実行では確認前のケースを採点せず、精度の数値を作りません。画像の季節・画角の違いを含む人による評価と、それに基づく重みの校正は残っています。

記録ファイルは以下の配列です。API の実料金が不明なときは `costUsd` を省きます。

```json
[{"queryId":"kamo-1","placeIds":["munich","ljubljana","seoul"],"latencyMs":1200,"fallback":false}]
```

上位3件の適合率、NDCG、候補を返せた割合、未採点の結果数、p95応答時間、記録された平均費用と代替検索率を集計します。結果は `.cache/evaluations/discovery.json`。記録ファイルを指定しない場合は、外部 API や写真解析を呼ばない特徴による順位の基準実行です。写真・地形の全工程の精度を測ったとは扱いません。

## 海の色

「雰囲気から」「写真の風景から」で、海の色を指定できます。指定なし、比較元の写真に近い色、ターコイズ、青、濃い青、緑、灰色、茶色から選びます。川・湖・池・プールは海として扱いません。

写真検索は既存の Gemini による写真の見比べと同じ呼び出しで色の根拠を取得し、異なる色の候補を除外します。海や色を判断できない候補は、不明値の設定に従い、確認できた候補の後に残すか除外します。雰囲気検索は、利用条件・被写体を確認した Commons 写真だけを必要時に解析します。1検索の追加確認は節約モードで最大6件、通常で最大18件。比較元の色を調べる場合もこの件数に含みます。公開写真の解析結果は、画像ハッシュ・モデル・プロジェクトを含むキーで7日間再利用します。アップロード写真の観察は永続キャッシュに保存しません。

色は撮影した写真の見え方であり、現在の海の色、透明度、水質、水深、遊泳可否を保証しません。結果の詳細で、観察の根拠と写真の出典を表示します。条件は共有URLとブラウザーに保存されます。衛星特徴だけを使う地形検索には適用せず、切り替え時に解除します。

## 街の雰囲気

街並みの見え方を、指定なし、比較元に近い、歴史ある街並み、現代的な街並み、低層の住宅街、緑の多い街並み、港町・海沿い、小さな町・集落から選べます。混在する特徴は最大3種類で記録し、比較元と近い条件では共通する種類があるかを確認します。

「雰囲気から」は、もともとの Maps を参照する候補検索と比較元の特徴確認の呼び出しで、街並みの分類・根拠・参照元を取得します。既に根拠を取得できた場合は、街の雰囲気のためだけに写真を追加解析しません。資料で分からない場合だけ、海の色と同じ確認件数の範囲で、照合済み Commons 写真を使います。「写真の風景から」は、既存の画像比較と同じ呼び出しで、見える建物・街路・緑・港の特徴を整理します。

結果は「写真での観察」と「Maps の資料からの解釈」を区別し、詳細に根拠と出典を表示します。街並みがないと確認できる写真・場所を、指定した街並みの一致として返しません。確認できない場合は不明値として扱います。海の色と街の雰囲気は同時に選べ、既知の不一致を除外したうえで、不明な候補を後に並べます。静かさ・活気・混雑・治安をこの分類から断定しません。地形検索への切り替え時は両条件を解除します。

海の色・街並みの写真観察には、自然な色の通常写真と確認できた画像を使います。Landsat・衛星・疑似カラー・赤外画像の情報がある参照画像や、解析で通常写真と確認できなかった画像は、色や街並みの根拠を不明として扱います。自然色の空撮写真は使えます。

追加の実 API 確認では、ロックアイランドの通常写真から青い海の根拠を取得し、川の写真を除外しました。ティケハウの Landsat 参照画像は不明として扱うことを確認しました。Maps の資料から歴史的な街並みの候補を取得し、Commons 写真の比較でも街並みの分類と根拠を取得しました。ブラウザーでは両条件の選択、再読み込み後の保持、地形モードでの解除、街並みを指定した実検索と根拠の表示を確認しました。CSS幅1280pxと390pxで横方向のはみ出しはなく、今回のUI拡張のレビューは `ship` です。画像は `.impeccable/review/scenery-desktop.jpg` と `scenery-mobile.jpg`。

比較元が既に選択されている場合は、同じ名前の別の街を引かないよう、地点名と選択中の都市・国を組み合わせて解決します。例えば「鴨川」を京都の地点として選んだ状態では、京都の川を参照します。

## 実際の写真検索の記録

`npm run eval:discovery` だけでは、写真や外部 API を使わない特徴の順位しか採点できません。公開中の写真検索と同じ処理で評価用のケースを実行するには、`npm run eval:record` を使います。順位、所要時間、代わりの検索になったかを `.cache/evaluations/search-runs-latest.json` に保存します。Google の有料 API を呼ぶので、`--limit=3` や `--ids=kamo-1,kamo-2` で件数を絞れます。

```bash
npm run eval:record -- --limit=3
npm run eval:discovery -- --results=.cache/evaluations/search-runs-latest.json
```

Google Maps の情報で代わりに探した結果は、Google の利用規約に合わせて場所の ID を保存せず、写真検索としては結果なしとして数えます。2026年11月10日に2件で動作を確認し、1件あたり最大約27秒かかりました。人による確認が済んだケースがないため、精度の数値はまだありません。

## 同じ検索の再利用と結果の共有

写真検索の結果は、登録カタログと Commons の写真だけで作ったものに限り、同じ条件の検索に24時間再利用します。条件は、出発点、特徴、地域、写真の比重、絞り込み、写真の索引の版、節約モードです。結果はサーバーのメモリーに最大200件置き、インスタンスごとに別々です。Google Places の情報は再利用せず、表示のたびに取得します。2026年11月10日の確認では、同じ検索の2回目が31秒から1.5秒になりました。

写真検索の結果を共有すると、リンクに登録カタログの ID を最大12件含めます。開いた人には、有料の API を呼ばずに同じ候補を表示します。写真で比べた理由は、もう一度検索すると表示されます。

雰囲気からの検索は Google Maps に基づく結果です。Google の利用規約（Service Specific Terms の Grounding with Google Maps）では、検索した本人に表示し、保存は評価などの目的に限られるため、ほかの人への再利用や共有はしません。共有リンクを開いた人が自分で検索します。

結果つきの共有を Firestore に保存するには、`npm run google:rules` でルールを反映します。反映前は、条件だけの共有に切り替わります。

## 写真の追加検索

写真がない地点や1枚だけの地点は、Commons で別の写真を探せます。写真がない地点だけを対象にする場合は `--missing` を使います。

```bash
npm run catalog:index -- --refresh --below=2
```

写真が見つからなかった地点は30日間探し直しません。地点の間を2秒空け、HTTP 429 では2分ずつ待ち時間を延ばして同じ地点をやり直し、5回続いたら止めます。進み具合は10地点ごとに保存するので、止まっても再実行で続きから進みます。写真ごとに Gemini による被写体の確認と埋め込みを行うため、有料 API の費用がかかります。

## 英語表示

画面右上と画面下の「English」で英語に切り替えます。日本語以外の言語を使うブラウザーでは最初から英語で表示し、`?lang=en` でも指定できます。画面の文言は `lib/i18n-en.ts` の訳を使い、訳の抜けはテストで確認します。

雰囲気からの検索では、Gemini に英語で書かせ、Google Places も英語で取得します。Google Maps に基づく回答を、あとから翻訳で書き換えないためです。登録カタログの説明、写真の比較、検索の説明はこのアプリが用意した文章なので、英語表示では Cloud Translation で英語にし、サーバーのメモリーに7日間置きます。画面の訳がある文は、その訳を使います。
