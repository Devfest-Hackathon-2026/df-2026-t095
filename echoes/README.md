# Elsewhere

好きな場所の風景や過ごし方から、次の行き先を探すウェブアプリです。画面は日本語で、スマートフォンとPCの両方で使えます。現在はローカルで動かし、Google Cloud プロジェクト `devfest-hackathon-hexagon` に接続しています。

## 起動

Node.js 22.13 以降が必要です。

```bash
npm ci
npm run dev
```

[ローカル版](http://127.0.0.1:5173/)を開いてください。認証は既存の `.env.local` と `gcloud` のログイン状態を使います。サーバー用のキーやアクセストークンはブラウザーへ渡しません。

別の環境で接続を作る場合は `.env.example` を参照してください。`npm run google:setup` は、指定プロジェクトの Firebase アプリ、用途を制限したキー、Firestore、匿名認証、ローカル設定を用意します。Firestore のルールは `npm run google:rules` で反映します。既存の設定がある環境では、内容を確認してから実行してください。

## 場所の探し方

「雰囲気から」は、Google Places で選んだ出発点について、Gemini が Google Maps の情報を参照して似た場所を探します。水辺、緑、カフェなどの特徴を選び、共通点と違いを比べられます。参照元は各候補に表示します。

「写真の風景から」は、ユーザーが写真を用意せずに使えます。既存12地点の写真を再利用し、登録した36地点のうち、被写体と利用条件を確認できた30地点の Commons 写真を比較対象にします。別の場所を入力した場合も Commons で写真を探しますが、場所名や所在地を照合できない写真は採用しません。写真が近くで撮られたという理由だけでは採用せず、Gemini でも景観が主な被写体か確認します。適切な写真が見つからない場合や画像埋め込みを使えない場合は、Google Maps の情報による検索に切り替わり、理由を表示します。地図の検索も使えない場合は、既存の紹介用データを表示します。

「写真の風景から」では、自分の写真も選べます。JPEG・PNG・WebP、8 MB・2,400万画素以内です。解析に使える権利を確認してから検索します。サーバーで向きを補正し、EXIF・GPS情報を除去して縮小した画像を Google に送ります。このアプリでは、アップロードした写真とその埋め込みを保存しません。撮影場所は未指定として扱い、距離や出発点のピンは表示しません。共有リンクに写真を含めることもありません。Google Maps / Google Earth の画面画像は受け付ける用途にしていません。

「地形から」は、Google Earth Engine の Satellite Embedding V1、Copernicus DEM、JRC Global Surface Water を使う試験機能です。Google の航空写真を見ながら対角の2点を押し、比較元の四角い範囲を選べます。緯度・経度での入力にも対応します。参照範囲は縦横100 m以上、一辺40 km以内・900 km²以内です。地点の周辺100 mを使う方法も残しています。

選んだ範囲の平均衛星特徴を、世界の登録地形18地点のうち、参照範囲から100 km以上離れた別の領域と比べます。同じ範囲や近接した地点を除外し、地点名、国・地域、距離を表示します。2024年の衛星データを使い、Google Maps の表示画像は取得・解析しません。データがある範囲の割合を表示し、比較できるデータがなければ理由を返します。

群島・ラグーン・環礁・メサ・ビュートの参照例を用意しています。地形の種類を確定する分類器ではなく、輪郭の抽出、島の配置の認識、世界全域の探索は未実装です。レグールの判定も未対応です。

## 写真の比較

モデルは、プロジェクトで画像入力を確認した `gemini-embedding-2` です。Google Cloud の `us` エンドポイントの `embedContent` に Commons の画像、または利用者が選んで解析用に変換した画像を送り、768次元の埋め込みを取得します。Google Maps / Places の写真から埋め込みを作ることはありません。

順位の初期設定は、写真の近さ6：選んだ特徴4です。画面のスライダーで0：10から10：0まで調整できます。写真の近さには、画像埋め込み55、Vision の被写体ラベル20、Gemini による地形・構図の見比べ25の比重を使います。補助信号が取得できない場合は、利用できた信号の合計で割り直します。画像埋め込みはコサイン類似度を0〜1に変換します。これを選んだ特徴と加重平均します。特徴は選んだ項目の近さと候補側の強さを組み合わせます。出発点の特徴が未確認の場合は、選んだ特徴が候補側にあるかを使います。地域の条件と出発点の除外を先に適用します。

緑・空・水といった一般的なラベルだけでは、Vision による一致とは扱いません。確度の低いラベルも使いません。埋め込みで選んだ上位6候補の写真を Gemini で見比べ、地形や構図が明らかに異なる候補を除外します。全件が不適切なら、無理に候補を表示せず、条件を見直す案内を出します。

この数値は順位を決める手がかりです。一致率や、同じ体験ができる確率ではありません。天候、構図、撮影時期にも影響されます。説明では、写真で見える水面・木々・建物などと、静かさ・混雑などの推定を分けます。

写真の比較対象は現在30地点です。埋め込みだけで世界中の未登録地点を検索する仕組みではありません。地名から探す場合、比較対象がない地域では、写真を使わない Google Maps 検索に切り替わったことを表示します。撮影場所が未指定のアップロード写真では Maps 検索を行わず、選んだ特徴による候補へ切り替わったことを表示します。「雰囲気から」でも同じ検索を利用できます。外部のベクトルデータベースは使用していません。

## 写真の出典とキャッシュ

既存12枚について、Commons API からファイルの説明、撮影者、ライセンス、ファイルID、SHA-1を再取得しました。記録は `data/commons-samples.json`、従来の出典は `lib/photo-credits.json` と `public/images/*.jpg.json` にあります。既存・追加の写真はいずれも CC BY または CC BY-SA です。追加した地点は `data/extra-places.json`、写真の照合結果は同じ Commons の記録に含めています。表示用の縮小・トリミングがあることも画面に記載します。

```bash
node scripts/visual/audit-commons.mjs
```

新しい写真では、ファイルの説明に場所名があることと、所在地の情報が一致することを確認します。必要に応じて Wikidata の名称を照合します。利用するライセンスは CC BY、CC BY-SA、CC0、Public Domain のうち、出典と利用条件のURLを確認できるものに限定します。これは自動照合なので、場所の同定に誤りが残る可能性はあります。

Commons 写真の埋め込みは `.cache/commons-embeddings/`、Vision の結果は `.cache/commons-vision/`、再取得を避けるための画像は `.cache/commons-images/` に保存します。画像キャッシュも出典とSHA-256を記録します。キャッシュには画像のID・SHA-1・実際に解析したバイト列のSHA-256・モデル・次元数・Googleプロジェクト・出典・撮影者・ライセンスを含めます。画像やモデルが変わると別のキャッシュになります。削除しても再作成できます。Gitやコンテナーのビルド対象には含めません。BigQuery の登録済み Commons 埋め込みも、ローカルキャッシュがない場合に再利用します。アップロード写真とその埋め込みは、この保存処理や BigQuery の登録対象にしません。

## 気候と国・地域で絞り込む

Köppen–Geiger の30区分から直接選ぶか、比較元と同じ区分だけを選べます。Beck et al. の1991〜2020年の分類（V3、約1 km、CC BY 4.0）を使い、地名や画像から気候を推測しません。水域の地点は最寄りの陸地、地形の参照範囲は範囲内の陸地で最も多い分類を使います。データが不明なら、同じ区分という条件を勝手に緩めません。これは現在の天気や体感温度の比較ではありません。

「観光客数が少なめの国・地域」は、世界銀行の国際観光客到着数が2019年に100万人未満だった国・地域を対象にします。同じ年で比較するための条件であり、現在の人気・混雑・安全性を表しません。データがない国・地域は、この条件では採用しません。出典と年は画面に表示します。

```bash
npm run data:climate   # Python 3。公式アーカイブから気候区分を取得し、SHA-256で確認
npm run data:tourism   # 世界銀行の同じ年の統計を取得
npm run google:catalog  # 公開地点・Commons 埋め込みを指定プロジェクトの BigQuery へ登録
npm run google:terrain  # 登録地形の領域データを Earth Engine で作成して BigQuery へ登録
```

BigQuery のデータセットは `elsewhere`、リージョンは `asia-northeast1`。テーブルは `places`、`commons_embeddings`、`terrain_regions` です。Google Places の名称・住所・写真を収集して保存する用途にはしません。現在のカタログ取得は500件までで、ベクトルインデックスは作成していません。大規模化には検索方法と応答時間・料金の検証が必要です。

地球儀は Google の `maps3d` を使います。地点を選ぶと2.2秒で近づき、「地球全体」で戻れます。地形は領域全体が見える距離に調整します。動きを減らす設定では即時に移動します。WebGLや3D表示を使えない環境では「地図」に切り替えられます。

## Google との接続

| サービス | 用途 |
| --- | --- |
| Maps JavaScript API | 地図、航空写真、3D地球儀、地点間のカメラ移動 |
| Places API | 入力候補、場所の詳細、雰囲気検索の写真 |
| Geocoding API | 地図で押した地点の住所・場所の解決 |
| Routes API | 許可した現在地からの経路 |
| Vertex AI / Gemini | Maps に基づく候補、Commons 写真の照合と説明 |
| Cloud Vision API | 被写体ラベルとランドマーク検出を写真比較の補助に使用 |
| BigQuery | 公開地点カタログ、Commons 埋め込み、登録地形の比較データ |
| Gemini Embedding 2 | Commons 写真とアップロード写真の画像埋め込み |
| Cloud Translation | 説明が英語で返った場合の日本語訳 |
| Firebase Authentication | 匿名ユーザーの認証 |
| Cloud Firestore | 保存した場所のID、検索条件、共有用の条件 |
| Secret Manager | サーバー用 Maps キーの保管 |
| Earth Engine | 範囲を限定した衛星・標高・水域の解析 |

保存情報は、このブラウザーの匿名ユーザーにひもづきます。Google アカウントでのログインや、複数端末間の同期は未実装です。共有リンクは条件を共有し、同じ画像結果を固定して保存するものではありません。Google の写真や場所の説明を Firestore に複製しません。現在地は「現在地から調べる」を押して許可したときだけ使い、保存しません。
